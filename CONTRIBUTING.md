# Contributing

## Setup

```bash
npm ci
npm run verify   # lint + format + types + tests + build + smoke + exports
```

`npm run verify` runs everything CI runs. Run it before opening a PR.

| Script                            | What it does                               |
| --------------------------------- | ------------------------------------------ |
| `npm test`                        | Run the test suite                         |
| `npm run test:watch`              | Watch mode                                 |
| `npm run test:coverage`           | Tests with coverage thresholds enforced    |
| `npm run lint` / `lint:fix`       | ESLint                                     |
| `npm run format` / `format:check` | Prettier                                   |
| `npm run typecheck`               | `tsc --noEmit` over `src` and `test`       |
| `npm run build`                   | Bundle ESM + CJS + types via tsup          |
| `npm run smoke`                   | Load the built `dist/` as a consumer would |
| `npm run check:exports`           | `attw` + `publint` on the packed tarball   |

## The one thing to get right: signature parity

The SDK's core job is reproducing a byte-exact, order-sensitive HMAC that the
server rebuilds independently. The server signs
`implode('', Arr::except($request->validated(), [...]))`, and Laravel's
`validated()` returns fields in **`rules()` order**, skipping absent ones.

That means **the order of `fields` in `src/internal/fieldOrders.ts` must match
the order of keys in the endpoint's FormRequest `rules()` method**, minus
`token`/`signature` (and `payment_mode`, which is sent but not signed).

When you touch an endpoint:

1. Open the matching FormRequest under
   `app/Http/Requests/Application/ExternalPaymentIntegration/` in the PayLink
   repo and read `rules()` top to bottom.
2. Mirror that order in `fieldOrders.ts`. The `sdk` key is checked against the
   params interface, so a typo is a compile error — but **order is not something
   the compiler can check for you.**
3. Add a golden vector (below).

### Golden vectors

`test/fixtures/golden-signatures.json` is generated by PHP using the same
primitive the server uses, with no Laravel or DB dependency. It is what proves
the JS and PHP implementations agree byte-for-byte.

```bash
php test/fixtures/generate-golden.php > test/fixtures/golden-signatures.json
```

Each case pairs a camelCase `input` (what an SDK caller passes) with `values`
(the exact ordered concatenation the server builds). The suite asserts both that
the SDK produces `expected` from `input`, and that `buildSignature(values)`
produces `expected`.

**Adding a field to an endpoint without adding a golden case means that field's
position is untested.**

## Retry safety

Requests are only ever replayed when replaying cannot double-charge: GETs,
anything carrying an `Idempotency-Key`, and calls explicitly flagged
`replaySafe` (pure reads such as check-status). If you add an endpoint, think
about which bucket it lands in before wiring it up — the default for a POST is
"do not retry", and that default should only be overridden deliberately.

## Style

Prettier and ESLint are enforced in CI. Beyond that:

- Explicit return types on functions.
- `import type` for type-only imports.
- Prefer a doc comment explaining _why_ over an inline comment restating _what_.

## Releasing

1. Bump `version` in `package.json` **and** `VERSION` in `src/version.ts` (the
   release workflow fails if they disagree — the User-Agent would otherwise
   report a stale version).
2. Update `CHANGELOG.md`.
3. Merge to `main`, then publish a GitHub Release tagged `v<version>`.

The release workflow verifies the tag matches `package.json`, runs the full
check suite, and publishes to npm with provenance.
